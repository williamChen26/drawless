# Coworker Presence Design

## 设计方向

Coworker 使用 **Pixel-Paper Diegetic Workspace（像素纸张场景化工作台）**。人物不是聊天入口图标，而是驻留在画布边缘、会递接任务和交付工作单的协作者。纸张、墨线和像素人物共同建立空间关系；所有表现都必须对应一个真实业务阶段。

## 产品心智模型

- 一个 room 就是一项持续推进的任务，不在 room 内创建第二个“新任务”。
- Coworker 是这项任务里的长期同事，不是聊天机器人；产品界面不出现 conversation、session、turn 等聊天术语。
- 用户后续输入的含义是“补充要求”“调整方向”或“继续推进”，而不是开启新会话或追问一条消息。
- 工作结果属于 room 的工作状态；完整过程称为“工作轨迹”或“协作记录”，不称为聊天历史。
- 如果用户确实要开始另一项任务，应通过创建新的 room 完成，而不是在 Coworker 入口里增加“新任务”按钮。

## 空间锚点

- 桌面端位于画布左上安全区，避开顶部工具、右侧样式面板、底部工具栏和左下缩放控制。
- Composer、审批单和结果便笺从人物右侧展开，视觉起点与人物手部或视线接近。
- 移动端人物停靠右下，交流界面从人物上方展开；长内容不能遮挡顶部栏或底部画布工具。
- 如果未来根据选区调整展开方向，只能读取 tldraw bounds，不能缓存第二份 shape 数据。

## 材料语义

| 材料 | 唯一语义 |
| --- | --- |
| 纸带 | 用户把一条任务交给 Coworker |
| 手绘云朵 | Coworker 正在理解或执行 |
| 剪贴板工作单 | 等待用户审批的画布计划 |
| 编辑部工作便笺 | Coworker 的完整说明或最终交付 |
| 完成回执 | 已被 shared 契约验证的真实工具结果 |

同一时刻只展示一个主物件。打开 Composer 时收起上一张结果便笺；审批占据舞台时锁定 Composer 入口；结果与完成回执合并在同一张便笺中。

## 视觉规则

- 墨色使用蓝黑，交互强调使用 Coworker 钴蓝；琥珀只代表等待，绿色只代表完成，红色只代表异常。
- 临时纸张使用暖米白、细墨线、轻微错位叠层和克制的硬阴影，避免统一圆角 SaaS 卡片。
- 正文优先使用高可读的人文宋体或无衬线字体；手写字体只用于思考气泡和状态批注。
- 人物标签固定在图片正下方，状态变化不改变整体布局。
- 长输出仅让便笺正文区域滚动，标题和完成回执始终可见。

## 动效规则

- 纸带交接是签名动效：完整任务从右侧出现，折叠成纸片并沿弧线进入人物，约 820ms。
- 思考、审批和便笺使用 180–380ms 的自然减速入场，不使用弹跳或弹性曲线。
- 只动画 `transform` 和 `opacity`，不在动效期间阻止画布交互。
- `prefers-reduced-motion` 下保留清晰的静态交接状态，并取消循环或位移动画。

## 可访问性与契约

- 人物入口、Composer、审批按钮和结果定位保持原生键盘语义及清晰焦点。
- 流式正文不逐 token 播报；单独的 live region 只播报阶段与最终摘要。
- 审批参数必须先通过 `packages/shared` schema；无法验证时不允许批准。
- 结果只保存 record ID，定位时重新查询 tldraw store，画布始终是唯一事实源。
