# Drew Presence Design

## 设计方向

Drew 使用 **Canvas-Born Liquid Workspace（画布生长的液态工作台）**。Drew 的活体光标本体是驻留在画布边缘的真实同事入口：用户既可以找他聊天、提问和反馈，也可以交代工作、审核计划并接收交付。统一的液态玻璃浮层、蓝黑墨色和冷白雕塑质感的 SVG 生物共同建立空间关系；所有表现都必须对应真实的沟通或工作状态。

产品定位和命名边界以 [Drew 产品定位](./coworker-product-positioning.md) 为准；本文只约束其在画布中的在场方式与视觉语言。

## 产品心智模型

- Drew 是具有稳定身份和连续关系的同事，不是需要管理 session 的聊天机器人。
- Room 是共同工作的场所和上下文，不是一次会话，也不等同于一次原子任务。
- 同一个 room 内允许自然聊天、讨论、工作交代、反馈、审核和多次交付；这些行为不要求用户创建或切换 session。
- 普通对话保持轻量；计划、审批、执行和交付使用结构化工作物件承载责任。
- 产品界面不出现 session、thread、turn、new chat 等实现术语，也不提供为了清空上下文而存在的“新建会话”。
- 完整过程称为“协作往来”或“工作轨迹”；它可以同时包含对话与工作事件，但不以 AI 消息轮次组织产品心智。

## 空间锚点

- 桌面端常驻画布左下安全区。Drew 本体是稳定锚点，不随工作阶段上下跳动；为 tldraw 底部工具栏和设备安全区保留间距。
- Composer、审批单、当前回应和结果便笺从 Drew 本体右侧展开，视觉起点与黑色沟通凹腔朝向一致。这一方向只承载“现在正在发生的事”。
- “协作往来”是回看当前 room 历史的全高左侧工作轨迹抽屉。它从画布左边缘覆盖式滑入，不推动画布，也不与当前工作物件并排竞争。
- 抽屉只由画布左边缘的“往来”账本页签显式打开。打开后 Drew 保持原位并位于抽屉覆盖层下方，以空间来源而不是面板拼接表达两者关系。待审批事项到达时，审批单优先于正在回看的抽屉。
- 如果未来根据选区调整展开方向，只能读取 tldraw bounds，不能缓存第二份 shape 数据。

## 交互状态模型

前端表现由四层单向派生关系组成。理解代码时应按这一顺序阅读，不能把四层 `kind` 当成四套并列的业务状态。

```text
conversation facts
  → presence.phase
  → workspace surface（用户当前打开什么）
  → primary artifact（人物旁唯一展示什么）
  → attention（收起后还需提醒什么）
```

### 1. `presence.phase`：Drew 事实上正在做什么

`phase` 由 conversation controller 的状态、最后一个有效内容块和待处理审批派生。它是业务事实的可见投影，不由按钮直接修改。

| `phase` | 事实含义 | 默认可见表达 |
| --- | --- | --- |
| `ready` | 当前没有进行中的工作 | Drew 安静驻留；点击人物打开 Composer |
| `listening` | Composer 正在接收输入 | 人物进入倾听表现，输入框保持主焦点 |
| `receiving` | 用户内容已经发送，服务端正在接收 | 短暂玻璃交接片，随后进入思考 |
| `thinking` | Drew 正在理解或组织回应 | 椭圆液态玻璃思考气泡 |
| `executing` | 受控工具正在工作 | 工作中的思考气泡与停止动作 |
| `speaking` | Drew 正在形成面向用户的正文 | 当前液态玻璃对话气泡 |
| `awaiting-approval` | 存在尚未处理的正式审批 | 琥珀文档玻璃审批单，始终高于普通回应 |
| `completed` | 当前轮次已经完成 | 普通回应，或由真实工具结果支持的交付预览 |
| `interrupted` | 用户停止了当前轮次 | 琥珀文档玻璃说明 |
| `error` | 当前轮次未能完成 | 红色文档玻璃说明 |

### 2. `surface.kind`：用户此刻选择查看什么

`surface` 是唯一允许本地保存的展示意图。它不改变后台工作，也不复制 conversation 事实。

| `surface.kind` | 用户意图 | 主区域行为 |
| --- | --- | --- |
| `closed` | 把 Drew 的工作表面收好 | 只保留人物、状态和必要注意力提示 |
| `current` | 查看此刻最重要的事实 | 按 `phase` 和真实内容选择一个主物件 |
| `composer` | 给 Drew 补充内容 | 隐藏旧主物件，只显示 Composer；`purpose` 只调整文案 |
| `delivery` | 阅读完整交付说明 | 把交付预览升级为完整文档玻璃说明 |
| `activity` | 回看当前 room 的协作往来 | 隐藏主物件，从左边缘打开历史抽屉 |

这些 surface 互斥是刻意设计：同一时刻只有一个主阅读或主操作焦点。关闭任意 surface 只改变可见界面，不取消请求、不清空草稿、不删除协作记录。

### 3. `artifact.kind`：人物旁唯一出现的主物件

`artifact` 不是存储状态，而是 `resolveCoworkerPrimaryArtifact(...)` 的纯派生结果。

优先级固定为：

```text
surface 不允许展示
  > 待审批
  > 用户玻璃交接片
  > 接收 / 思考 / 执行
  > 错误或中断说明
  > 已验证画布交付
  > 普通对白
```

| `artifact.kind` | 出现条件 | UI |
| --- | --- | --- |
| `none` | `closed`、`composer`、`activity`，或没有可展示事实 | 不渲染主物件 |
| `handoff` | 新消息刚提交且没有更高优先级审批 | 进入 Drew 的短暂玻璃交接片 |
| `thought` | `receiving`、`thinking` 或 `executing` | 椭圆液态玻璃思考气泡 |
| `approval` | 存在待处理审批 | 可核对、批准、退回或暂缓的琥珀文档玻璃 |
| `dialogue` | 有正文且不属于画布交付 | 液态玻璃对话气泡 |
| `issue` | 错误或中断阶段且有正文 | 红色 / 琥珀文档玻璃说明 |
| `delivery-preview` | 存在真实画布结果，surface 为 `current` | 精简交付预览与成果定位入口 |
| `delivery` | 存在真实画布结果，surface 为 `delivery` | 完整文档玻璃说明与完成回执 |

### 4. `attention.kind`：表面收起后还不能丢失的提醒

`attention` 只装饰人物入口，不打开第二个面板。

| `attention.kind` | 触发事实 | 清除方式 |
| --- | --- | --- |
| `none` | 没有新事实，或用户已经看过 | 无 |
| `reply` | 新回应已完成但尚未查看 | 打开或主动收好当前表面 |
| `approval` | 仍有待处理审批 | 只有处理审批后才真正消失 |
| `delivery` | 有新的真实画布交付但尚未查看 | 打开或主动收好当前表面 |

### 状态如何配合

- 用户点击 Drew：如果已有当前物件，打开 `current`；否则打开 `composer`。
- 用户发送：请求立即开始，Composer 让位给 `current`；短暂 `handoff` 后由真实 `phase` 决定思考、执行或回应。
- 新回应、新审批或新交付：每个稳定 presentation key 最多自动打开一次；用户收好后不会被同一事实反复打断。
- 用户打开“协作往来”：切换到 `activity`，主物件隐藏，历史抽屉从左侧出现。
- 回看期间出现审批：自动切回 `current`，让必须决策的审批单获得焦点。
- 用户查看完整交付：`current → delivery`；点击成果定位后收起表面并把焦点交还 tldraw。
- 用户要求调整计划或交付：进入带对应 `purpose` 的同一个 Composer，不创建新的聊天模式或第二套任务状态。

## 浮层语义

| 浮层形态 | 唯一语义 |
| --- | --- |
| 对话气泡 | 用户与 Drew 的普通聊天、提问和简短反馈 |
| 玻璃交接片 | 用户把一段重要信息或工作交代递给 Drew |
| 思考气泡 | Drew 正在理解、思考或组织回应 |
| 琥珀文档玻璃 | 等待用户审批的画布计划 |
| 中性或语义色文档玻璃 | Drew 的正式说明或完整交付 |
| 完成回执区 | 已被 shared 契约验证的真实工具结果 |
| 液态玻璃抽屉 | 回看当前 room 的协作往来 |

同一时刻只展示一个主工作物件，避免计划、审批和完整交付彼此竞争。轻量沟通入口可以与主工作物件共存，但必须降低视觉权重；审批期间仍允许用户提出问题或要求调整，正式授权只能通过明确审批动作完成。结果与完成回执合并在同一个文档玻璃中。

## 表面生命周期

- 持续保存的是协作事实与工作状态，不是覆盖画布的浮层。对话、审批和交付都允许用户随时“收好”，收起动作不得取消后台工作或丢失协作往来。
- 人物入口统一控制 Drew 协作空间的展开与收起。再次展开时优先恢复当前回应、待审批事项或最近交付；没有可恢复内容时才打开 Composer。
- 新回应、新审批或新交付首次到达时自动展开一次。用户主动收起后不重复抢占画布；待审批事项仍在人物入口持续显示“等你确认”。
- 长回应先展示可读摘要，并允许在原浮层内“阅读全文”；完整内容只滚动正文区，不强迫用户进入协作往来。
- 用户选择“看画布成果”后，交付浮层自动收起并把焦点交还画布。定位结果时最高保持 100% 缩放，避免小对象被放大到遮蔽上下文。
- “协作往来”承载完整、可追溯的事实记录，不承担阅读当前回应或关闭当前工作物件的必经路径。

## 视觉规则

- 墨色使用蓝黑，交互强调使用 Drew 钴蓝；琥珀只代表等待，绿色只用于在线或完成，红色只代表异常。
- Drew 的所有浮层统一使用液态玻璃，但不统一成同一种圆角矩形：对话和思考使用椭圆或有方向的气泡轮廓，输入与控制器保持紧凑，审批和交付使用高可读文档玻璃。
- “协作往来”抽屉容器保持透明且不使用传统外阴影，画布侧通过由左向右衰减的暗化层保障可读性；用户消息、Drew 消息和工作事件分别使用独立玻璃片承载。
- 画布边缘的“往来”入口与 Drew 本体下方的身份基座沿用同一套 `control` 玻璃材质，作为抽屉的空间线索；SVG 本体和入口按钮不玻璃化。
- Drew 的文字标识与状态点收在同一个固定宽度玻璃基座中，SVG 底部轮廓与基座轻微重叠。状态点使用灰、绿、蓝、琥珀和红表达离线、在线、工作、等待与异常，同时由文字和可访问名称补足语义。
- SVG 本体保留原始冷白雕塑材质、黑色沟通凹腔和局部状态光；避免霓虹暗色 AI 科技感。主体后方使用低透明度、轻微错位并随五种 shell 形态一起变化的蓝黑墨影，在浅色画布上建立边界；墨影不是固定黑底、外框或独立卡片。注意力小球的黄绿色接缝是稳定识别纹，不表示在线或完成；琥珀只用于 `awaiting-approval`。
- 液态玻璃的材质与应用边界统一遵循 [Drawless Liquid Glass Material](./liquid-glass-material.md)；业务组件不能各自调整 blur、折射或兼容分支。
- 不支持 `backdrop-filter` 或用户偏好减少透明度时，玻璃片回退为高不透明度的浅色表面；不能把透明效果作为文字可读性的前提。
- 正文优先使用高可读的人文宋体或无衬线字体；手写字体只用于思考气泡和状态批注。
- 身份玻璃基座固定在 SVG 本体正下方，状态文案变化不改变整体布局；焦点环落在基座，SVG 只提供克制的位移、折叠与接缝反馈。
- 长输出仅让文档玻璃正文区域滚动，标题和完成回执始终可见。

## 动效规则

- 玻璃片交接是签名动效：重要信息或工作交代从右侧出现，凝聚成小片并沿弧线进入人物，约 820ms。
- 思考、审批和文档浮层使用 180–380ms 的自然减速入场，不使用弹跳或弹性曲线。
- 协作往来只使用一次约 300ms 的左侧滑入和更快的遮罩淡入；关闭时按相反方向滑出，不增加持续折射或循环变形。
- 只动画 `transform` 和 `opacity`，不在动效期间阻止画布交互。
- `prefers-reduced-motion` 下保留清晰的静态交接状态，并取消循环或位移动画。

## 可访问性与契约

- 人物入口、Composer、审批按钮和结果定位保持原生键盘语义及清晰焦点。
- 流式正文不逐 token 播报；单独的 live region 只播报阶段与最终摘要。
- 审批参数必须先通过 `packages/shared` schema；无法验证时不允许批准。
- 结果只保存 record ID，定位时重新查询 tldraw store，画布始终是唯一事实源。
