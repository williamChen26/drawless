# Coworker Presence Design

## 设计方向

Coworker 使用 **Pixel-Paper Diegetic Workspace（像素纸张场景化工作台）**。人物是驻留在画布边缘的真实同事入口：用户既可以找他聊天、提问和反馈，也可以交代工作、审核计划并接收交付。纸张、墨线和像素人物共同建立空间关系；所有表现都必须对应真实的沟通或工作状态。

产品定位以 [Drawless Coworker 产品定位](./coworker-product-positioning.md) 为准；本文只约束其在画布中的在场方式与视觉语言。

## 产品心智模型

- Coworker 是具有稳定身份和连续关系的同事，不是需要管理 session 的聊天机器人。
- Room 是共同工作的场所和上下文，不是一次会话，也不等同于一次原子任务。
- 同一个 room 内允许自然聊天、讨论、工作交代、反馈、审核和多次交付；这些行为不要求用户创建或切换 session。
- 普通对话保持轻量；计划、审批、执行和交付使用结构化工作物件承载责任。
- 产品界面不出现 session、thread、turn、new chat 等实现术语，也不提供为了清空上下文而存在的“新建会话”。
- 完整过程称为“协作往来”或“工作轨迹”；它可以同时包含对话与工作事件，但不以 AI 消息轮次组织产品心智。

## 空间锚点

- 桌面端位于画布左上安全区，避开顶部工具、右侧样式面板、底部工具栏和左下缩放控制。
- Composer、审批单和结果便笺从人物右侧展开，视觉起点与人物手部或视线接近。
- 如果未来根据选区调整展开方向，只能读取 tldraw bounds，不能缓存第二份 shape 数据。

## 材料语义

| 材料 | 唯一语义 |
| --- | --- |
| 对白便签 | 用户与 Coworker 的普通聊天、提问和简短反馈 |
| 纸带 | 用户把一段重要信息或工作交代递给 Coworker |
| 手绘云朵 | Coworker 正在理解、思考或组织回应 |
| 剪贴板工作单 | 等待用户审批的画布计划 |
| 编辑部工作便笺 | Coworker 的正式说明或完整交付 |
| 完成回执 | 已被 shared 契约验证的真实工具结果 |

同一时刻只展示一个主工作物件，避免计划、审批和完整交付彼此竞争。轻量沟通入口可以与主工作物件共存，但必须降低视觉权重；审批期间仍允许用户提出问题或要求调整，正式授权只能通过明确审批动作完成。结果与完成回执合并在同一张便笺中。

## 表面生命周期

- 持续保存的是协作事实与工作状态，不是覆盖画布的浮层。对话、审批和交付都允许用户随时“收好”，收起动作不得取消后台工作或丢失协作往来。
- 人物入口统一控制 Coworker 协作空间的展开与收起。再次展开时优先恢复当前回应、待审批事项或最近交付；没有可恢复内容时才打开 Composer。
- 新回应、新审批或新交付首次到达时自动展开一次。用户主动收起后不重复抢占画布；待审批事项仍在人物入口持续显示“等你确认”。
- 长回应先展示可读摘要，并允许在原便笺内“阅读全文”；完整内容只滚动正文区，不强迫用户进入协作往来。
- 用户选择“看画布成果”后，交付便笺自动收起并把焦点交还画布。定位结果时最高保持 100% 缩放，避免小对象被放大到遮蔽上下文。
- “协作往来”承载完整、可追溯的事实记录，不承担阅读当前回应或关闭当前工作物件的必经路径。

## 视觉规则

- 墨色使用蓝黑，交互强调使用 Coworker 钴蓝；琥珀只代表等待，绿色只代表完成，红色只代表异常。
- 临时纸张使用暖米白、细墨线、轻微错位叠层和克制的硬阴影，避免统一圆角 SaaS 卡片。
- 正文优先使用高可读的人文宋体或无衬线字体；手写字体只用于思考气泡和状态批注。
- 人物标签固定在图片正下方，状态变化不改变整体布局。
- 长输出仅让便笺正文区域滚动，标题和完成回执始终可见。

## 动效规则

- 纸带交接是签名动效：重要信息或工作交代从右侧出现，折叠成纸片并沿弧线进入人物，约 820ms。
- 思考、审批和便笺使用 180–380ms 的自然减速入场，不使用弹跳或弹性曲线。
- 只动画 `transform` 和 `opacity`，不在动效期间阻止画布交互。
- `prefers-reduced-motion` 下保留清晰的静态交接状态，并取消循环或位移动画。

## 可访问性与契约

- 人物入口、Composer、审批按钮和结果定位保持原生键盘语义及清晰焦点。
- 流式正文不逐 token 播报；单独的 live region 只播报阶段与最终摘要。
- 审批参数必须先通过 `packages/shared` schema；无法验证时不允许批准。
- 结果只保存 record ID，定位时重新查询 tldraw store，画布始终是唯一事实源。
