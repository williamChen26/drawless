## 验证

本机 Node 24.5.0 / pnpm 9.15.0。默认 `pnpm check` 已包含：

- shared：12 个测试；server：25 个测试；coworker：14 个测试；web：79 个测试，共 130 个。
- 所有 5 个包的类型检查；shared、ui、server、coworker 和 Next 的构建。
- 真实 WebSocket：服务端确认、第二客户端收到 shape、普通断线重新 hydration、离线/关闭/取消拒绝写入。
- 真实 Mastra（本地假 provider，不联网）：审批前不执行工具、审批后执行一次、防重放、保留受信房间权限。
- runtime 生产 smoke：匿名 custom API / 默认 agents API 拒绝、任意出站目标拒绝、有效凭据 start → online → stop。
- Next 生产 smoke：首页生成独立签名房间、房间页面正常响应。
- 工作区与独立 runtime 构建目录的依赖审计：本次均为 info/low/moderate/high/critical = 0。

独立只读审查发现的审批提前消耗、旧 cursor 记忆、跨页箭头绑定均已修复并针对性复审通过。实际 Mastra 测试另发现恢复工具会持有原上下文：采用进程内受信能力对象，在已验证审批恢复时更新同一对象的权限和取消信号；没有通过放宽跨房间校验绕过问题。

没有完成的验证：真实模型效果与费用、完整浏览器多标签端到端、Linux 干净容器执行、持续负载/故障注入和部署平台实际配置。CI 配置已加入，但本轮没有推送，也没有声称线上 CI 已通过。
